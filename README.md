# DBDP

<br><br>

**Discord Bot Development Project**

Backend 및 Frontend 기술 향상을 위한 디스코드 봇 개발 및 웹, DB, API, table 등을 실습해보는 프로젝트입니다.

## SCOPE

### 필수

- **디스코드 계정 로그인**<br>
  웹에서 디스코드 계정으로 로그인하고, 같은 계정으로 봇이 사람을 구분

- **사람별 설정 페이지**<br>
  목소리(성별), 언어, 읽기 속도 등 개인 설정

- **봇 기능 설정 페이지**<br>
  서버 단위로 TTS 채널, 기본 목소리, 읽기 규칙 등 봇 동작 설정

- **봇 권한 설정 페이지**<br>
  역할·사람별로 봇 기능 사용, 설정 변경, 차단 권한 지정

- **사람별로 다르게 반응하는 봇**<br>
  음성 채널에서 메시지 작성자의 설정에 맞춰 TTS로 읽기

- **배포**<br>
  웹 페이지 공개, 봇 상시 실행

<br>

### 도전 (시간이 되면)

- 서버마다 다른 개인 설정 (이 서버에서만 다른 목소리)
- 웹에서 목소리 미리듣기
- 디스코드 안에서 명령어로 설정 변경
- 설정 변경 기록
- 개인 게임 프로젝트와 계정 연동
- 발음 사전<br>
  기본 사전(예: `ㅋㅋ` → "크크")을 제공하고, 사용자가 항목을 켜고 끄거나 직접 추가<br>
  기본 사전 · 서버 사전(관리자) · 개인 사전 3단계, 개인 → 서버 → 기본 순으로 적용

## 진행 순서

<br>

### 0단계 · 준비

- [ ] 저장소 만들기, 파일마다 README 작성
- [ ] 협업 규칙 정하기 (Fork + Pull Request, PR 작성 양식)
- [ ] 각자 테스트용 디스코드 서버 만들기
- [ ] 토큰 · 비밀번호 같은 비밀 값은 저장소에 올리지 않는 규칙 정하기

> ✔ 완료 기준: 저장소와 README, 협업 규칙이 정리됨

<br>

### 1단계 · Git 이해

- [ ] Git 구조 이해: 작업 폴더 → 스테이징 → 로컬 저장소 → 원격 저장소
- [ ] 커밋 · 브랜치 · 병합(merge) 개념 이해
- [ ] 명령어 익히기: clone, status, add, commit, push, pull, branch, switch, merge, log
- [ ] Fork + Pull Request 실습, 충돌(conflict) 일부러 만들어보고 해결하기

> ✔ 완료 기준: 팀원이 Fork해서 첫 PR(README에 이름 추가 등)을 올리고 merge까지 해봄

<br>

### 2단계 · 스택 구조와 동작 원리 이해

- [ ] 웹 동작 원리: 브라우저가 요청을 보내고 응답을 받기까지 (HTTP, JSON)
- [ ] 프론트엔드 · 백엔드 · DB 각각의 역할과 구조, 서로 연결되는 방식 (API, CORS, 로그인 상태 유지)
- [ ] 디스코드 로그인(OAuth)이 동작하는 흐름
- [ ] 기술 스택 비교 후 확정, 작은 예제로 기초 실습 (예: 메모 저장 페이지)

> ✔ 완료 기준: "웹에서 버튼을 누르면 DB에 저장되기까지"의 흐름을 그림으로 설명할 수 있음

<br>

### 3단계 · 설계

- [ ] 페이지별 화면 스케치 (로그인, 내 설정, 내 서버 목록, 서버 설정, 권한 설정)
- [ ] 저장할 데이터 정리 (사람별 설정, 서버별 설정, 권한)
- [ ] 필요한 요청(API) 목록 정리 — 어떤 화면에서 어떤 데이터를 주고받는지
- [ ] 봇이 읽어갈 데이터 형식 정하기, "정해야 할 것" 2가지 확정

> ✔ 완료 기준: 화면 스케치, 데이터 목록, API 목록이 문서로 정리됨

<br>

### 4단계 · 뼈대와 연결

- [ ] 웹 · 서버를 각각 최소한으로 실행되게 만들기
- [ ] 웹 → 서버 → DB 연결 확인 (웹에서 보낸 값이 DB에 저장됨)
- [ ] 봇 → DB 연결 확인 (봇이 DB에 저장된 값을 읽음)

> ✔ 완료 기준: 웹에서 값을 저장하면 봇이 그 값을 읽어서 디스코드에 출력함

<br>

### 5단계 · 디스코드 계정 로그인

- [ ] 웹에서 "디스코드로 로그인"
- [ ] 로그인한 사람의 이름·프로필 사진 표시
- [ ] 로그아웃

> ✔ 완료 기준: 로그인하면 내 디스코드 이름이 웹에 보임

<br>

### 6단계 · 사람별 설정 ⭐ 핵심

- [ ] 내 설정 저장·불러오기
- [ ] 내 설정 페이지 (목소리, 언어, 속도 등)
- [ ] 봇이 메시지 작성자의 설정을 찾아서 그 목소리로 읽기

> ✔ 완료 기준: 같은 채널에서 나는 남성 목소리, 친구는 여성 목소리로 읽힘

<br>

### 7단계 · 봇 기능 설정 (서버별)

- [ ] 내 서버 목록 (봇이 있는 서버, 봇 초대 버튼)
- [ ] 서버 설정 페이지 (TTS 채널, 기본 목소리, 읽기 규칙)
- [ ] 봇이 서버 설정대로 동작

> ✔ 완료 기준: 웹에서 TTS 채널을 바꾸면 봇이 바뀐 채널만 읽음

<br>

### 8단계 · 봇 권한 설정

- [ ] 권한 설정 페이지 (역할·사람별로 TTS 사용 / 설정 변경 / 차단)
- [ ] 서버에서 권한 검사 — 권한 없는 사람은 설정을 바꿀 수 없음
- [ ] 봇이 권한대로 동작 (차단된 사람 메시지는 읽지 않음)

> ✔ 완료 기준: 권한이 없는 계정으로 다른 서버 설정을 바꾸려 하면 막힘

<br>

### 9단계 · 보안 점검

- [ ] 서로의 기능을 직접 공격해보기 (남의 설정 바꾸기, 권한 우회, 도배 등)
- [ ] 찾은 문제 고치고 기록 남기기

> ✔ 완료 기준: 찾은 취약점과 수정 내용이 문서로 정리됨

<br>

### 10단계 · 배포와 마무리

- [ ] 웹 · 서버를 공개 주소로 올리고, 봇을 24시간 실행되는 곳에 올리기
- [ ] 실제 디스코드 서버에서 테스트
- [ ] 사용 방법, 화면 캡처 README에 정리, 발표 자료 만들기
- [ ] 회고 — 잘된 점, 아쉬운 점, 다음에 해볼 것

> ✔ 완료 기준: 내 컴퓨터를 꺼도 웹과 봇이 정상 동작하고, README만 보고 사용할 수 있음
### 🟡 도전 과제는 언제?

- 5단계 이후 → 목소리 미리듣기, 디스코드 명령어로 설정 변경
- 7단계 이후 → 발음 사전, 서버마다 다른 개인 설정, 설정 변경 기록
- 필수가 다 끝난 뒤 → 게임 계정 연동
